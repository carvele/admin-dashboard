# Code Remediation Ultra: Controlled Code Fixes

This skill provides the standard operating procedure for remediating findings generated by \code-review-ultra\. It strictly separates diagnosis from treatment and requires independent validation before modifying code.

## 🚨 Core Remediation Philosophy
- **Do Not Blindly Trust the Audit:** Before changing anything, independently validate that the finding actually exists and the proposed recommendation is safe.
- **Finding-by-Finding:** Do not batch refactor the feature. Address issues one at a time.
- **Minimal Appropriate Change:** Implement the smallest, safest fix that resolves the root cause. Avoid rewriting entire files.
- **No Opportunistic Refactoring:** While fixing a finding, do not modify unrelated code merely because it appears old, inconsistent, or improvable. Record unrelated concerns for a future audit/remediation task.
- **Never Erase Audit Evidence:** The original finding and evidence must remain immutable in the audit report. Your output is a separate *Remediation Report*.

## 🛠️ Remediation Workflow

For every finding assigned to you from the audit report, execute the following steps in order:

### 1. Confirm Finding Still Exists
* Read the exact file and line referenced in the audit.
* Verify the code still matches the evidence and the issue is real.
* *If the finding is erroneous, a hallucination, or lacks evidence, reject the fix and document why.*

### 2. Understand Root Cause
* Trace why the issue occurs. Is it a typo, a fundamental logic flaw, or a misunderstood domain contract?

### 3. Check Affected Dependencies
* Trace the inputs/outputs of the target code using \grep_search\ or similar tools.
* What other files, components, or database tables rely on this exact behavior? 
* Will this fix silently break them?

### 4. Implement Minimal Appropriate Change
* Apply the safest, most targeted fix possible to resolve the root cause.
* Respect existing project conventions and architecture.

### 5. Add / Update Regression Test
* If applicable, add or update tests (e.g., Jest) to cover the fixed behavior.

### 6. Run Verification
* Statically verify the fix (e.g., \
px tsc --noEmit\).
* Run the test suite if applicable.

## 📋 Remediation Report Format
Produce a markdown remediation report tracking the action taken on each finding. Do not modify the original audit report.

**[Finding ID / Title]**
* **Validation:** (Confirmed to exist / Rejected due to X)
* **Root Cause:** (Brief explanation of why it was failing)
* **Dependency Check:** (What else relies on this, and is it safe?)
* **Applied Change:** (Summary of the minimal fix applied, or "Deferred")
* **Verification Status:** (e.g., Passed \	sc\, manual runtime check required)
